## 4. 正式卡牌接入：两种方式，选一种

### A. 简单卡牌：用默认动作钩子

继承 `AbstractDoubleCard` 的卡牌可以覆盖：

```java
@Override
public String getDefaultCharacterAnimation() {
    return CharacterAnimationController.ATTACK_MAGIC;
}
```

保持 `shouldPlayDefaultCharacterAnimation()` 为 `true`。`modcore.receiveCardUsed()` 会读取这个名字并调用控制器；有自定义名字时不会再补默认剑击。技能牌也可以通过这个钩子指定施法或强化动作。

这一方式使用 `IGNORE_IF_BUSY`，角色忙碌时可能跳过本次请求。它不等待动画完成，也不保证伤害命中时刻与画面刺出时刻一致。

**分流要求：** 上例只适用于已经确定使用 INNER 的卡牌/角色。在同一张卡牌支持表里两种形态时，必须依据正式形态状态返回各自的动作名，不可把里角色名字直接应用到全部表角色卡牌。目前没有现成的完整形态状态接口，后续需要明确实现。

### B. 需要控制时机：手动播放

在 `use()` 中直接调用控制器，或加入动作队列：

```java
addToBot(new SS.action.common.PlayCharacterAnimationAction(
        CharacterAnimationController.CAST_S,
        CharacterAnimationRequest.Policy.INTERRUPT));
```

同时覆盖：

```java
@Override
public boolean shouldPlayDefaultCharacterAnimation() {
    return false;
}
```

直接调用会立即发起请求；队列调用在对应游戏 Action 执行时发起请求。`PlayCharacterAnimationAction` 发起后马上完成，**不是等待整段动画的阻塞动作**。需要命中时刻同步时，应另行设计事件/延迟，不要以为加入队列就自动同步了。

不要既在 `use()` 手动播放，又让默认钩子播放同一个动作。

## 5. 播放策略与回到 idle

| 策略 | 实际行为 |
| --- | --- |
| `IGNORE_IF_BUSY` | 非 idle 动作未结束时忽略新请求 |
| `INTERRUPT` | 可切换到另一个动作；同名动作未结束时不会重启 |
| `FORCE_RESTART` | 同名动作也重新从头开始，适合临时测试或明确要求重播 |

正常动作由 `AbstractSSCharacter.playCharacterAnimation()` 播放一次，然后自动排队循环 idle。不需要在卡牌里额外调用 reset；立即 reset 反而会截断动画。

连续动作可以调用 `playSequence(policy, ...)`，但现有 `attack_combo` 本身已经是完整连击，不必拆成多个平 A。

找不到请求名字时，控制器可能回退 idle，或默认出牌路径回退 `attack_sword`。所以“没有崩溃”不等于播放了正确动作，必须检查日志 selected 名字。

## 6. 受伤与死亡：已有接口，不重复加补丁

- `PlayerHurtAnimationPatch.java` 在实际扣血且角色仍存活时播放 `hurt`，不需要每张伤害卡再触发一次。
- `AbstractSSCharacter.playDeathAnimation()` 已覆盖原版死亡方法，按当前加载的骨架寻找 `death`。
- 表角色死亡停在倒地末帧；里角色死亡停在完全消散的空白末帧。两者都不排队回 idle。
- 死亡开始后普通动画和 reset 被拒绝，防止 hurt/出牌覆盖死亡。
- `renderCorpse` 是原版私有字段，当前通过 `ReflectionHacks.setPrivate(...)` 设为 false，以继续渲染 Spine。**不要改成 `this.renderCorpse = false`**，之前会产生访问权限错误。
- 不要调用普通 `CharacterAnimationController.play("death", ...)` 来正式处理死亡，因为普通接口会排队回 idle。
- 不要再次 patch `AbstractPlayer.die()`：此前目标方法不存在，导致 ModTheSpire 启动失败。

## 7. 资源维护与衔接原则

游戏实际读取的是 `src/main/resources/img/char/spine_inner/` 中整套 `character.json`、`character.atlas` 和 atlas 引用的 PNG 页。预览 GIF、MP4、逐帧目录不会自动进入运行时。

- 更新时使用同一版本完整 export，不能只复制 JSON 或遗漏 atlas 页面。
- 不覆盖 `spine/`；表角色这一版冻结。
- 动画资源采用逐帧图片附件。衔接是否自然取决于图片本身，不要指望 Spine 的混合时间能替代中间帧重绘。
- 首尾与 idle 对齐头部高度、双脚落点、身高和比例；测量人物本体，不把剑尖、火焰、马尾飘动边界作为缩放依据。
- 必须缩放修正时让变化平滑分布，不在尾帧突然缩小；避免每帧按整张前景包围盒自动归一化。
- 图片应匹配亮度、发色、服装色和面罩；检查半透明火焰和透明边缘，避免侵蚀手脚、剑或金属面罩。
- 预览默认 60 FPS，同时保留逐帧 PNG 文件夹。GIF 的调色板/透明限制可能产生毛边，最终应同时检查 PNG 与游戏内效果。

最终里角色含死亡的完整候选导出为 `art_candidates/character_runtime_v53_death/export/`；当前运行时以 `spine_inner/` 为准。表角色最新导出为 `art_candidates/character_runtime_v54_front_death/export/`，不要交叉复制。


目前 POM 的 package 步骤自动复制到以下两个游戏位置，因此这是部署操作，不只是本地编译：

```text

E:\SteamLibrary\steamapps\common\SlayTheSpire\mods\DoubleSS.jar
E:\SteamLibrary\steamapps\common\SlayTheSpire\DoubleSS\content\DoubleSS.jar
```

核对三者 SHA256 一致，退出并重新启动游戏后测试。若显示 “Nothing to compile” 却怀疑代码没有更新，应检查 JAR 内实际 class，不要只凭 BUILD SUCCESS 判断。

曾经 IDE 输出过含 `Unresolved compilation problem` 的 class；必要时关闭冲突的自动编译、执行可靠的重新编译，并用 `javap -c` 核对 `MyCharacter` 的 FRONT/INNER 常量及死亡方法的 ReflectionHacks 调用。

## 9. 排查动画播错、没播放、结束突变

调试文件为游戏工作目录下 `DoubleSS-animation-debug.log`，通常在 SlayTheSpire 根目录。关注：

- 初始化实际 atlas / JSON 路径是否为 `spine_inner`。
- `request animations=...` 与 `result=playing selected=...` 是否对应。
- `missing-animation=...`、`fallback-used=...`、`ignored-busy` 是否出现。
- 死亡应出现 `death-result=playing animation=death loop=false`。

**历史关键问题：** 其他 mod 曾拦截 Spine 的 String 重载，按子串把 `cast_s` 匹配为 `cast_special`。当前控制器先精确 `findAnimation()`，再传入 Animation 对象，已解决。不要把它改回 `state.setAnimation(0, "cast_s", false)`。

尾帧回 idle 突变时，先比较相同画布下头部、脚底、身体宽度、手部姿势和颜色，不要先怀疑加载路径，也不要只调整游戏整体 scale。
