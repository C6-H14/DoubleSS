# Spine 角色拆分与动画问题记录

适用对象：DoubleSS 角色战斗骨骼，Spine 3.8.75。

## 本轮已经出现的问题

1. **独立补全肢体改变了可见轮廓**
   - AI 补全图虽然沿用了原切片高度，但宽度、轮廓和隐藏关节位置发生变化。
   - 继续使用旧切片中心坐标时，静止姿势已经出现横向偏位；旋转后偏差进一步放大。
   - 处理原则：原图可见像素和原始裁切尺寸拥有最高优先级。补全内容只能出现在原图不可见的关节遮挡区，不能替换外露轮廓。

2. **只校验完整人物轮廓，没有逐关节校验**
   - 静止缩略图看似完整，不代表肩、肘、腕、髋、膝、踝和剑柄握点正确。
   - 处理原则：每个关节必须分别检查静止、蓄力、命中、收势四个关键帧。

3. **骨骼轴心依靠目测估算**
   - 肩点、肘点和腕点略有偏差时，手臂旋转会产生明显断层或不自然重叠。
   - 处理原则：先用原图重叠区域确定关节中心，再设置骨骼原点；不得先做大幅动画再用图片位置补偿错误轴心。

4. **剑绑定到手骨，但握点没有单独标定**
   - 剑会跟随手移动，但剑柄与掌心可能发生滑动。
   - 处理原则：记录剑柄握点和手掌握点的同一世界坐标；所有关键帧检查两点是否重合。

5. **刚性图片旋转会暴露隐藏边缘**
   - 当前部件不是网格权重变形，大角度旋转容易露出切口、空洞或不一致的补全部分。
   - 处理原则：首期限制关节旋转幅度并扩大原图关节重叠；只有确认刚性方案无法通过时才增加网格和权重。

6. **导入路径可能沿用上一次 JSON**
   - Spine 导入框中过长路径会被截断显示，曾误把旧 V2 数据另存成 V3。
   - 处理原则：每次使用系统文件选择器点选目标 JSON；导入后立即展开 `root` 和动画列表核对骨骼名、动画名。

7. **动画名称与代码约定不一致**
   - 早期使用了 `attack_slash`，而设计文档约定为 `attack_sword`。
   - 处理原则：正式动画创建前先锁定名称；导入后检查动画树，禁止依靠工程文件名推断动画名。

## 后续每个动画的强制检查清单

- [ ] 静止姿势与获批角色原图叠加检查，可见轮廓无位移。
- [ ] 肩、肘、腕、髋、膝、踝分别放大检查，无缝隙、跳边和错误遮挡。
- [ ] 前后肢体的绘制顺序正确，运动过程中不会突然互换前后关系。
- [ ] 手掌握点与武器握点在全部关键帧重合。
- [ ] 动画第 0 帧与 setup pose 一致。
- [ ] 动画最后一帧完整回到 setup pose，避免切回 `idle` 时跳变。
- [ ] 命中事件只出现一次，并位于视觉接触帧。
- [ ] 用原尺寸与游戏显示尺寸各预览一次；缩小后仍能读出动作方向。
- [ ] 检查动画名、持续时间、循环设置和事件名。
- [ ] 保存新版本，不覆盖上一个可回退工程。

## V5 首轮复核记录（2026-09-17）

- 工程：`DoubleSS_character_attack_sword_aligned_v5.spine`
- 数据源：`DoubleSS_character_side_attack_sword_aligned_v5.json`
- 静止姿势：改回 `side_body_v1` 后，衣服、裙摆、双臂和双腿的整体轮廓已重新贴合获批原图；不再使用改变外露轮廓的 V2 AI 补全肢体。
- 预备帧（约 0.12 秒）：持剑手腕的连接基本连续，但远侧膝部在旋转后会显出原始裁切边界，需要局部隐藏补片或收小膝关节旋转。
- 命中帧（约 0.28 秒）：大幅抬剑会把肩、肘、腕的隐藏区带到可见区域；下一步应逐关节放大检查，不允许再次整体重绘手臂。
- 当前结论：V5 可以作为正确对齐基线，但还不是最终可交付动画；局部补片完成前不得把它替换为游戏正式资源。

## 下次制作时的额外硬性规则

- 拆分后先做“原图重组测试”：所有部件以零旋转叠回去必须与原图逐像素一致，再开始绑骨。
- 每个旋转关节必须预留朝运动方向至少一段隐藏覆盖区；覆盖区只能向衣物或身体内部延伸。
- AI 只允许绘制透明区里的隐藏延伸，不得改动已存在的非透明像素；生成结果必须与原切片做差分检查。
- 动作幅度先用灰模或骨骼线确认，再检查图片缝隙，避免同时修改动作和素材而无法判断误差来源。
- 每次只修一个关节，并保存递增版本；禁止一次替换整套部件后才做总体验收。

## 帧动画流程新增问题与规则

- 五帧横向生成图中，长剑可能跨过按画布等分得到的单元格边界；直接按固定格宽裁切会截断剑尖。
- 处理方法：先根据透明通道识别每个“人物＋长剑”的连通区域，再按原单元格的身体中心放入统一透明画布。
- 所有正式帧统一为 `1024×768`，身体中心和脚底基准不随剑的包围盒宽度变化，避免长剑方向改变时人物左右跳动。
- 在 Spine 中只切换同一插槽的 attachment，不再拆分四肢，因此不会产生腿间三角形和关节裂缝。
- 导入后必须检查第1帧、最大蓄力帧、第8帧命中以及第15帧；长剑在所有帧均需完整显示。
- 图集导出时启用透明区域裁切和旋转打包，源帧统一画布不等于运行时必须为每帧保留整张 `1024×768` 纹理。

## `attack_sword` V1 播放复核新增问题

1. **双马尾展开过度**
   - V1 在挥剑时把两侧头发画成了大面积横向散开的发束，与已确认侧身图中收束的双马尾不一致。
   - V2 规则：马尾根部、长度和整体体积固定；只允许末端产生小幅滞后，不允许横向膨胀。

2. **人物发生逐帧漂移**
   - V1 虽然使用统一画布，但生成阶段没有锁死骨盆中心与两个鞋底接地点，导致身体在画布内小幅平移。
   - V2 规则：同时锁定骨盆注册点、左鞋接地点和右鞋接地点；旋转和屈膝必须围绕这些锚点发生，禁止用整个人平移表达重心。

3. **挥砍终点过低**
   - V1 剑刃从高位一直跟随到膝部和地面方向，攻击观感更像失去控制的下砸。
   - V2 规则：剑刃在胸部高度的前方完成攻击，接近水平或只略微向下；在该高度制动后回位。

4. **15帧、0.8秒显得仓促**
   - V1 的蓄力、加速、制动和收剑缺少中间帧，尤其从高位到命中姿势变化过快。
   - V2 调整为24帧、约1.2秒，并把额外帧优先分配给蓄力末端、加速过程、胸前制动和回位。

5. **V2 草图初稿出现剑路折返**
   - 初稿第9～12帧中剑先向前、又跳回竖直方向，不能作为正式绘制依据。
   - 已重新绘制：第8～13帧的剑角度必须单调地由后上方旋转至胸前水平位置，不允许中途反向。

6. **整张生成容易把过渡帧画成重复停顿**
   - 第13～18帧曾完全一致，第19～21帧又突然跳变并重复，不能视为增加了帧数。
   - 处理规则：复杂区间拆成独立连续条带生成和验收。当前把第9～14帧作为攻击过渡段，把第16～22帧作为回收段。
   - 每个中间帧至少要在剑角、手部位置、肘部弯曲、肩胸旋转或重心中体现连续变化；禁止仅复制相邻姿势。

7. **第10帧需要明确的空间约束**
   - 剑刃指向北偏西60°，即屏幕上大约为朝左上、比水平向西高30°。
   - 剑柄末端和双手经过人物中轴略靠右的位置；不能用剑刃角度正确来掩盖握点的横向错位。

8. **透视剑姿不能只按屏幕平面角度绘制**
   - 第12帧方向采用坐标向量 `(3,-1,-1)`：x 轴朝屏幕外、y 轴从左到右、z 轴从下到上。剑主要朝观察者伸出，屏幕投影略向左下，因此必须有明显透视缩短，并横在胸前形成防护。
   - 第13帧方向采用 `(3,2,-0.5)`：仍主要朝观察者伸出，屏幕投影转向右侧并轻微向下。
   - 长剑必须只有护手前方的一段剑刃；护手后方只能是剑柄与剑首。禁止把透视重叠误画成双头剑。

## AI 视频转帧流程的已验证经验（2026-09-18）

### 已跑通的正式流程

1. 使用相同的粉色背景首尾帧生成固定机位视频。
2. 先查看完整源视频的等间隔接触表，不直接按固定帧数抽取。
3. 删除过长前后摇、重复停顿帧和动作突变帧；需要补间时回到原视频取时间中点帧。
4. 人物与武器使用 MatAnyone 连续抠图；新出现的符文或投掷物不能只依靠首帧遮罩，需要按自身颜色或差分单独提取。
5. 所有选中帧使用同一个全局缩放和位移。禁止逐帧按包围盒适配，否则人物会忽大忽小、脚底漂移。
6. 首帧和尾帧替换为同一张原始透明母版，并核验文件哈希完全一致。
7. 在黑底、白底和游戏背景上检查透明边缘，然后才允许打包 Spine Atlas。
8. Spine 运行时继续使用单插槽 attachment 切帧；动画最终以 3.4 JSON 和多页 Atlas 进入游戏。

### 抠图与透明边缘

- 粉色背景并不保证能够直接色键。生成器可能加入粉色放射光、地面亮斑、阴影和渐变；这些效果与背景同色时会被误判成前景扇形杂块。
- MatAnyone 适合连续的人物和武器，但不保证保留首帧中不存在的新物体。`cast_attack_1` 的金色 S 因此采用“人物 MatAnyone + 金色符文独立色键”的双路合成。
- MatAnyone 的 foreground RGB 会对粉色背景做互补色补偿。半透明边缘虽然 alpha 看似正常，在 Spine 线性过滤后可能出现绿色轮廓。
- 正式清理规则：对 `0 < alpha < 248` 的像素，用最近的 `alpha >= 248` 内部像素重建 RGB，alpha 保持不变；完全透明像素 RGB 必须清零。
- Atlas 每个裁切区域必须向外复制边缘 texel，避免透明邻域在线性过滤下产生黑边或彩边。

### 帧选择与时长

- 视频最小时长为 4 秒不代表游戏动画也应保留 4 秒。先按动作阶段选帧，再以 40～50 FPS 播放，常规攻击和施法目标为约 0.7～0.9 秒。
- “增加帧数”必须增加真实中间姿势。复制相邻帧只能形成停顿，不能修复动作不连续。
- 判断补间优先观察：剑柄和剑尖轨迹、双手、骨盆、头部、两个鞋底接地点。人物轮廓相似不等于动作连续。
- 删除帧或插帧时必须保存“新帧号 ← 原视频帧号”映射，后续修改始终以映射为准，不能凭 GIF 新编号猜源帧。

### 武器与人物一致性

- 剑长、剑柄、护手、剑尖必须逐帧标定。生成视频和人工补尖都可能造成剑长突变，从而产生“软剑”观感。
- 补全被画幅裁断的剑时，禁止凭感觉直接延长。先选取同一动作、同一透视关系中剑完整且最清晰的一帧，分别标出剑柄与剑身连接处、剑尖中心点，测量两点间的标准中心线长度；再在待修帧标出相同的剑柄连接点和现有剑轴，沿该轴补到标准长度。补完后必须逐帧复核剑柄—剑尖距离、剑身宽度和剑尖轨迹，防止补成过长、过短或弯剑。
- 如果缺失部分原本位于视频画幅外，必须给整组帧增加完全一致的透明边距，并让每帧人物做相同平移；只扩大单帧或缩放单帧会造成游戏内人物跳动。新增区域仅补缺失剑段，不能重绘已经可见的剑柄、手部或人物。
- 标定结果应保存为可复查的数据（参考帧号、剑柄点、剑尖点、标准长度、目标帧补完点），同时输出带描点参考图，后续同类修补优先复用该数据而不是重新目测。
- “长度参考帧”和“纹理模板帧”可以不同：长度取透视关系最接近且剑完整的一帧；纹理必须取剑身无遮挡的一帧。若模板中手指、衣服或特效遮住剑身，仿射复制后会出现断节或光棒状补段。实体剑应复制真实金属刀刃/附魔边缘纹理并仿射贴合；只有独立剑气轨迹才允许用连续曲线补画。
- 有透视缩短时不能用屏幕投影长度判断真实剑长；仍需同时检查握点、方向和消失点。
- 人物尺寸以已在游戏内确认的首帧可见包围盒和脚底线为基准，不以源视频整张画布尺寸为基准。
- 上衣必须始终束在裙腰内；裙腰束带属于裙子。提示词中禁止“上衣下摆飘动”，并在接触表中单独检查腰部。
- 双马尾只允许发梢产生小幅惯性，发根、总体长度和体积必须保持收束。

### 视频提示词的结构规则

- 最重要的身份和朝向约束必须放在开头、每个动作阶段中重复，并写成可见的画面关系；只在提示词末尾写一次通常不足以压制模型的姿势先验。
- 避免同一提示词同时要求互相竞争的构图。例如“侧身”“双脚并拢”“剑位于身体正前方”“端正对称十字架”会让模型优先选择最容易满足后三项的正面构图。
- “面向右侧”含义不够精确，模型可能只让脸或视线朝右。应分别约束：肩线、胸口、骨盆、膝盖和脚尖均维持侧向右前方，人物不得展示左右对称的正面胸口。
- “左腿向后跨一步并到右脚边”同时包含深度方向和屏幕位置，容易产生歧义。应明确右脚为固定锚点，左脚只移动，并描述最终左脚在右脚的画面左后侧或右后侧位置。
- 手指数量和精确手势属于小尺度细节，容易被全身动作模型忽略。必须把该手势安排在稳定停顿阶段，并避免同时要求身体转向、移动武器和生成强特效。
- 特效不得只写“不要越界”。有投掷物时必须写明投掷方向、可见飞行范围、在画面内的爆炸位置以及爆炸最大半径。
- 纯粉背景必须显式排除：地面、人物影子、脚下投影、背景渐变、放射光、水平光束和环境亮斑。

## `cast_buff` 第一次生成失败分析（即梦 6807，2026-09-18）

- 源视频：97 帧，约 24.15 FPS，4.0167 秒。
- 第 1 帧保持正确侧身待机；第 5 帧已经明显向镜头转身；第 9 帧起成为完全正面姿势，直到约第 84 帧才开始回到侧身。
- 主因不是单独一句朝向约束缺失，而是提示词内部的构图竞争：
  - “笔直站立”；
  - 双脚收拢；
  - 剑放在腹部正前方并竖直向上；
  - 左手与剑形成“清楚、端正的十字架”。
  这些描述共同构成强烈的正面对称姿势。模型选择正面构图，可以同时更容易地满足竖剑、并腿和十字架，因而压过“身体朝向右前方 30～45 度”及末尾的“不能面向屏幕”。
- “全程人物必须面向右侧”放在提示词后段且只出现一次，属于抽象禁止项；生成模型不会把它当成逐帧几何锁。应在动作开头和每个阶段重复肩、胸、骨盆、膝盖、脚尖的侧向关系。
- “左腿向后跨一步并到右脚边”存在语义歧义。“跨一步”暗示明显位移，“并到右脚边”又暗示对称并腿；模型以转正并腿解决冲突。正确版本应为“右脚全程钉在原地，只有左脚向后内侧滑撤并收拢”。
- 剑被放到了屏幕中轴，并长时间遮挡脸部。这来自“腹部正前方、剑尖正上方、端正十字架”。侧身版本必须规定剑位于人物身体中轴的画面右侧，剑身从脸部右侧经过，不能穿过面部中线。
- 左手没有稳定形成“食指和中指横在剑前”的小手势，而是在伸臂、摊掌和祈祷手势之间变化。全身视频模型难以在身体转向和移动剑的同时维持两根手指的精确拓扑。
- 金色光效被生成成全身描边和贯穿整个画面的水平光束，而不是“沿剑向全身涌动一次”。这是“十字架 + 金色力量 + 强化”的常见视觉先验。后续必须禁止水平光束，并把光流路径拆成剑身→右手→双臂→躯干→双腿的短时顺序。
- 视频中出现脚下地面亮斑/阴影，违反透明素材要求。后续提示词需把“无地面、无影子、无脚下亮斑”放入开头的场景定义，而不只放在末尾负面限制。
- 上衣束入裙腰和双马尾收束总体比朝向执行得更好，但回位阶段头发体积仍有所扩大，仍需在接触表中复核。

### `cast_buff` 下一版必须使用的核心几何描述

- 右脚是唯一固定锚点，全程位置、朝向和鞋底接地点不变。
- 左脚向人物后方和内侧小幅滑撤，收至右脚的左后侧附近；左脚不得越过右脚，也不得与右脚重叠。
- 肩线、胸口、骨盆、两个膝盖与脚尖全程朝向画面右前方；观众只能看到身体的左前侧和部分正面，绝不能看到左右对称的正面胸口。
- 竖剑位于人物画面右侧，剑身从右肩和脸部右侧经过，不能占据屏幕中轴或遮挡脸部。
- 左手两指横向手势在身体和剑已经稳定后再完成；吟唱期间身体不再转向。
