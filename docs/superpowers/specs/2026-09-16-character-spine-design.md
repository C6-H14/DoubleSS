# 二硫键角色 Spine 骨骼动画—设计记录

> 状态：需求澄清中。本文记录已确认结论、原始问答摘要和未决事项；在最终设计确认前不作为实施完成说明。

## 目标

以 `E:\图与psd\img\DoubleSS\char\Character.psd` 为角色原画，制作可在《杀戮尖塔》DoubleSS Mod 中运行的 Spine 战斗角色动画，并保留静态角色图作为加载失败时的回退。

首期动画范围：

- `idle`
- `hit`
- `attack_sword`

后续允许扩展任意“特殊动作”，包括但不限于特殊攻击、攻击施法、非攻击施法、骰子动作和其他卡牌专属动作。

## 环境与路径

- Mod：`D:\StSmod\DoubleSS`
- 美术资源：`E:\图与psd\img\DoubleSS`
- 游戏：`E:\SteamLibrary\steamapps\common\SlayTheSpire`
- Spine：`E:\图与psd\Spine3.8.75破解版`
- Photoshop 2020：`C:\Program Files\Adobe\Adobe Photoshop 2020\Photoshop.exe`
- 禁止误用 Photoshop 2022。

Spine 3.8.75 是唯一制作版本，不回退到 Spine 3.4.x。若游戏旧 Runtime 无法读取 3.8 导出数据，首选制作受控的 JSON 兼容转换流程，不优先升级游戏 Runtime。

## 素材选择与备份

- 人物主体严格采用 `Character.psd` 的脸、发型、服装和身体比例。
- `PreAnim.psd` / `PreAnim.png` 仅作为长剑造型和持剑姿态参考，不替换人物主体。
- 允许补画肩部、袖口内前臂、裙摆遮挡的大腿上端、双马尾根部等骨骼旋转所需区域。
- 允许清理当前静态图的横向背景拉伸痕迹。
- 原始 `Character.psd` 和 `Character.png` 不得覆盖；所有改动在副本中进行。
- 备份保存在 E 盘一份即可。
- 当前 E 盘约剩余 37.91 GB；若后续空间不足，则在 `D:\StSmod` 下建立工作目录。

### PSD 实际检查结果（2026-09-16）

- `PreAnim.psd`：1024×1024，只有一个智能对象图层；不能直接取得人物或长剑的独立分层，只能作为视觉参考，或从整图中重新抠取长剑。
- `Character.psd`：350×350，共 8 个图层；主要是若干整图版本、蒙版和通道混合器调整层，图层名称仍为“图层 2/3/4/...”等默认名称。
- `Character.psd` 没有按头发、五官、四肢、衣服、裙摆等身体部件分层，不能直接运行 PhotoshopToSpine 脚本得到可用骨骼素材。
- 正式制作必须从整幅角色图重新切件，并补全所有被遮挡关节；`Character_rig.psd` 将是新建的规范分层工程，而不是简单整理原 PSD 图层。
- 检查期间未保存或修改任何 PSD，Photoshop 最后恢复为原先活动的 `PreAnim.psd` 标签。

## 美术与动画风格

- 风格暂定为活泼、有弹性；仍需原作者确认。
- 衣服保持正常材质，不发光。
- 长剑始终握在角色右手，待机时剑尖朝屏幕右下方。
- 普通攻击为单次长剑斜斩；角色主要朝屏幕右侧的敌人出招。
- 首期只制作一种普通斜斩。
- 不添加挥剑音效。

### `idle`

- 呼吸与身体轻微起伏。
- 双马尾弹性摆动。
- 裙摆轻微摆动。
- 每 2～5 秒随机眨眼一次，闭眼约 0.1～0.15 秒。
- 不制作发光效果。

### `hit`

- 首期暂定只在实际扣除生命值时播放。
- 闭眼、身体后仰、头发和裙摆产生惯性。
- 致死伤害仍尝试先播放一次 `hit`，随后进入现有 `Corpse.png` 死亡表现；不得为了完整播放动画而破坏或长期延迟游戏死亡流程。
- 受伤判定将在二期重新详细设计。

角色受到伤害至少存在四个需要区分的阶段：

1. 无伤；
2. 伤害被格挡；
3. 未完全防住，但伤害被 `AbstractAlly` 挡下；
4. 角色实际扣血。

### `attack_sword`

- 右上蓄力后朝敌方完成一次斜斩。
- 收势后返回持剑待机。
- 动画播放期间，后续普通挥剑请求默认忽略，避免连续出牌时角色反复抽搐。
- `hit` 与高优先级特殊动作可以中断普通挥剑。

## 卡牌动作触发设计

- 首期仅玩家从手牌主动打出的攻击牌触发普通挥剑。
- 自动打出、复制、回响等非主动出牌首期不触发普通挥剑。
- 角色主动打出的所有来源的攻击牌默认映射到 `attack_sword`，包括无色牌、活动牌和其他 Mod 的牌。
- “主动打出”首期按 `type == ATTACK && !isInAutoplay && !dontTriggerOnUseCard` 识别；若某个机制未正确设置这些标记，再为该机制补充识别。
- 普通挥剑在玩家打出卡牌的瞬间开始，不等待实际伤害结算。
- 单张牌可以通过设置一个变量或覆写一个函数，改为不播放、播放其他动作或动态选择动作。
- 单张牌未来可以播放多次动画，且每次可以相同或不同；复杂牌应能关闭默认挥剑，并在自身 Action 队列的指定位置插入角色动画 Action，以便和多段伤害、攻击施法或其他效果同步。
- 复杂卡牌动画默认不阻塞游戏结算；需要同步命中时，由卡牌显式插入 `WaitAction` 或对应同步 Action。
- 动画请求支持普通忽略、强制中断和强制重播等策略，使“连续普通攻击不抽搐”和“单牌明确连斩多次”能够同时成立。
- 手动指定的动画不存在时记录明确错误日志，同时忽略该次请求并保持当前动画，不自动回退为普通挥剑。
- 二期可能为自动出牌增加一个特殊施法动作，以兼顾未来移植《杀戮尖塔 2》的需求。

计划在 `AbstractDoubleCard` 提供统一扩展点，在 `AbstractSSCharacter` 集中处理动画播放与优先级。特殊动画不存在时必须安全回退，不得导致战斗崩溃。

建议的开放动作分类包括：

```text
DEFAULT
NONE
ATTACK_SWORD
SPECIAL
CAST
```

具体 Spine 动画名称与动作分类分离，以便扩展：

```text
special_dice
special_record
cast_buff
cast_other
```

## 状态和优先级

暂定优先级：

```text
hit > 特殊动作 > attack_sword > idle
```

- 普通挥剑播放期间忽略新的普通挥剑请求。
- 动作结束后回到 `idle`。
- 暂停时不强制切换动画状态；是否视觉上继续推进由游戏自身暂停行为决定。
- Save & Load 不额外序列化一次性动作的动画名、轨道时间或排队状态；重建战斗场景后从 `idle` 开始。
- 战斗结束或切换房间时，通常前一个一次性动作已经结束；没有其他动作上下文时默认使用 `idle`。
- Spine 加载失败时显示现有静态 `Character.png`。
- 获得格挡、受到治疗、充能骰子等行为首期不触发角色动作。

## 绑定技术路线

采用混合绑定：身体与四肢以刚性拆件为主，双马尾、裙摆、袖口使用有限 Mesh 和权重。为兼容旧 Runtime，首期避免路径约束、物理约束、剪裁附件、复杂嵌套变形以及其他 Spine 3.8 高级特性。

服装结构锁定：腰部横向束带属于裙子而不是上衣；上衣塞入裙子。首期束带与百褶裙融合为单一 `skirt` 附件并随骨盆层级移动，通过 Mesh 权重让束带区域较硬、下方裙摆柔和摆动。`torso` 不包含束带，但应在束带后方补出少量隐藏的塞入式下摆，避免躯干旋转露缝。

正式拆图前先制作一套最小 Spine 3.8 测试资源，验证游戏能否直接加载。若失败，则对照游戏现有 Spine 3.4.02 JSON，开发仅覆盖本项目实际字段的 3.8 → 旧格式转换流程。

## 工作分工

- 目标是由 Codex 尽可能直接操作 Photoshop 2020、Spine 3.8.75，并完成 Mod 接入和测试。
- 若 Spine 图形界面操作确实无法可靠自动完成，则回退为：Codex 处理素材、代码、转换工具和详细操作指导，用户完成必要的 Spine 编辑器步骤。
- 用户自述美术功底较弱，因此回退方案必须提供足够具体的逐步指导和验收图。

## 问答摘要

1. 首期范围？`idle + hit + attack`。
2. 动画风格？暂定活泼、有弹性，等待原作者确认。
3. 普通攻击？使用长剑挥砍；特殊攻击和其他特殊动作后续扩展。
4. 能否补画？允许，但必须备份原始图片和 PSD。
5. 面部动画？首期眨眼和轻微嘴部变化，后续完善。
6. 卡牌触发？攻击牌默认普通挥剑，单牌可配置其他动作；代码按开放动作系统设计。
7. 是否保留静态回退？保留。
8. 自动化程度？尽量由 Codex 直接完成，必要时回退到用户操作 Spine。
9. 兼容方案？固定 Spine 3.8.75，优先转换 JSON。
10. Photoshop？使用 Photoshop 2020，禁止使用 2022。
11. 待机持剑？始终右手持剑，剑尖向右下。
12. 人物是否参考 `PreAnim` 改造？人物严格保持 `Character.psd`，`PreAnim` 仅作武器和姿态参考。
13. 连续攻击？普通挥剑过程中忽略后续普通挥剑请求。
14. 声音？首期不添加。
15. 攻击牌覆盖范围？主动打出的所有来源的攻击牌，包括无色牌、活动牌和其他 Mod 的牌。
16. 主动出牌识别？首期使用 `!isInAutoplay && !dontTriggerOnUseCard` 等标记，后续针对例外机制修正。
17. 挥剑时机？出牌瞬间开始。
18. 显示尺寸？匹配当前 `Character.png` 的占屏高度和脚底位置。
19. 嘴部变化？`idle` 保持微笑，`hit` 使用轻微受伤表情。
20. 致死伤害？仍尝试播放 `hit`，随后进入现有死亡表现。
21. 单牌动作次数？必须支持一张牌播放多次相同或不同动画。
22. 复杂牌是否默认阻塞结算？不阻塞；需要同步时显式插入等待或同步 Action。
23. 缺失动画？记录错误日志，忽略该请求并保持当前动画。
24. 治疗、格挡、充能等动作？首期不制作，保持 `idle` 或当前有效动作。

## 未决事项

- 原作者对“活泼、有弹性”风格的确认。
- 350×350 原图是否直接作为工作分辨率，或先放大后再切件和补画。
- `Character.psd` 的逐部件精确切分边界与遮挡补画清单。
- Spine 3.8.75 导出资源能否被游戏当前 Runtime 直接读取。
- 如何准确识别“玩家从手牌主动打出”，并排除自动打出、复制和回响。
- 多动画卡牌的阻塞/非阻塞语义、缺失动画回退和与伤害 Action 的同步规则。
- Save & Load 后重建场景并回到 `idle` 的实际表现。
- 二期四阶段受伤反馈设计。
- 二期自动出牌的特殊施法动作。

## 最终确认的美术生产方式

- `Character_rig.psd` 使用 1400×1400 工作画布，即原始 350×350 的四倍尺寸。
- 从 `PreAnim` 中抠取长剑，修复被手遮挡的剑柄后，再按 `Character` 的右手和比例适配。
- 隐藏区域允许使用 AI 辅助补画，因为现有素材本身均为 AIGC；硬性约束是当前可见区域不得改变。
- AI 美术流程采用非破坏式候选方案：允许使用 Image 2 对角色的现有可见像素进行高清重绘，不再要求逐像素保持原图，但这是“忠实高清重制”，不是重新设计角色。`Character.png` 是脸部气质、外貌、头身比例、双马尾轮廓、服装版型与细节、配色、袜子和鞋等全部可见设计的唯一基准；不得擅自幼态化、成熟化、改变身材比例或改款服装。任何明显的外貌或衣服偏差都必须修正。先确认高清完整角色基准图，再以同一基准图逐件生成透明 PNG，避免直接从放大后模糊的原图抠件。所有生成结果先保存为候选，不得覆盖原始 PSD 或原始 PNG。
