# 表角色动画修复 v56

2026-09-29；针对《表角色动画全面排查_20260929.md》的问题制作。

## 已实施

- 平 A、攻击施法一、重击、减益、强化、攻击施法二、指挥、特殊施法、受伤：从旧普通 Alpha 图集正确提取，去除贴边污染后转换为预乘 Alpha。
- 祈祷：从封存的 `preview_v9_matanyone_grounded/alpha_frames` 原始 RGBA 重建，未沿用 v55 错误反预乘的颜色。
- 去污染只替换靠近正常主体颜色的粉紫边缘 RGB，保留透明度；紫色剑光和减益烟雾的大色块受到保护，不全局删色或侵蚀人物。
- 以当前 idle 的头部、鞋底与脚区中心校正站立首尾。依据端点计算整个动作的平滑校正，不按跳跃/跪地的每帧包围盒自动缩放。
- 10 个普通动作的开头与末尾均使用准确 idle，并加入短光流过渡；死亡不排队回 idle。
- 清理受伤原视频遗留在两鞋之间的棕色地面残线；不改伤害与受伤播放逻辑。
- 所有动作运行时时长保持原值；普通动作输出约 60fps 时间线，末帧保持到原动画结束时间。
- idle 全部 180 张纹理像素保持一致。死亡的 151 个区域 Alpha/几何与时间线保持一致，仅处理局部污染颜色，起始纹理恢复为准确 idle。
- 表角色图集重新打包，里角色资源与修复前 JAR 逐文件比对一致。

## 验证

`art_candidates/character_runtime_v56_front_repaired/validation.json` 保存检查结果：

- 所有正在使用的纹理区域，RGB 通道均不超过 Alpha：预乘约束违规为 0。
- 10 个普通动作的首尾像素与 idle 完全相同。
- idle 与 death 时间线保持不变；原动作结束事件与时长保留。
- GIF 采用整段固定调色板、无抖动、不透明深灰/浅灰底，回读核对总延时；每份 GIF 都有逐帧 PNG 文件夹和 MP4。
- GIF 仅支持 10ms 延时粒度，约 60fps 由 10/20ms 交替表达；MP4 和 PNG 更适合观察全色边缘。不可将 GIF 视为精确半透明 RGBA。

本轮已检查接触图与重点动作的末段过渡图，没有进行游戏内全部卡牌的实际试放。短光流过渡可能存在轻微软化，仍需实际播放复测；中段正常姿势变化与设计特效不等同于污染。
